# DUSRM 0.8 — Semantic Validation Method

**Status:** Draft; non-normative

## 1. Validation pipeline

A description is assessed in distinct stages:

1. JSON parsing.
2. JSON Schema Draft 2020-12 validation.
3. Semantic cross-reference and consistency checks.
4. Profile registry compatibility checks.
5. Evidence-status checks.
6. Human review of scope, layer allocation, safety, security, and claims.

The current CLI performs stages 1–5 for a selected subset. Human review remains outside the software.

## 2. Implemented checks

| Rule family | Implemented behavior |
|---|---|
| Identifier integrity | Detect duplicate participant identifiers and duplicate IDs within typed collections |
| Realization integrity | Resolve element and responsibility references; detect duplicate realization pairs |
| Responsibility allocation | Report non-applicable/unrealized responsibility cases as warnings |
| Relationships | Resolve sources, targets and optional scope references |
| Operation/state ownership | Resolve operation owners and state-variable subjects |
| Transition semantics | Resolve transition subjects and optional state-variable references; check endpoints against declared finite values |
| Evidence integrity | Resolve evidence references; require supporting evidence and a method for verified claims |
| Profile compatibility | Resolve profile IDs/versions and require explicit `compatible` registry status |
| Extension safety | Require profile extension keys to be namespaced |
| Maturity consistency | Flag promoted relationship/realization claims that conflict with planned or simulated endpoints |

## 3. Finding severities

- **Error:** the description fails the implemented semantic checks.
- **Warning:** the description may be usable, but an unresolved or unallocated condition must be disclosed.
- **No findings:** the current implemented rules found no issues; this is not full conformance.

## 4. Out of scope

The current validator does not yet establish:
- every relationship participant signature;
- full profile composition compatibility;
- arbitrary temporal logic correctness;
- invariant proof validity;
- safety/security or regulatory compliance;
- implementation behavior from source code;
- adequacy or truthfulness of evidence beyond basic metadata checks.

## 5. CLI

```bash
python scripts/validate_semantics.py conformance/fixtures/valid-minimal.json
python scripts/validate_semantics.py conformance/fixtures/valid-minimal.json --json
```

A description that references a profile marked `not-assessed` in the registry receives an error. This is intentional: candidate version does not imply compatibility approval.
