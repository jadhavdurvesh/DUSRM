# Validation

DUSRM must be evaluated against systems with different characteristics. Case studies should test whether the model can describe structure, behavior, state, resources, interfaces, constraints, failures, and lifecycle without forcing product-specific abstractions.

Initial candidate case studies:
- ANANTA: database and computational engine.
- FireBot: integrated cyber-physical robotics system, including software, hardware, autonomy, power, sensing, safety, and fleet coordination.
- A small standalone application: ensure the model is usable without distributed infrastructure.

For each case study, record the system boundary, model mapping, unmapped concepts, ambiguities, assumptions, and proposed changes to DUSRM. Case studies do not prove universal applicability; they provide evidence and expose limitations.
